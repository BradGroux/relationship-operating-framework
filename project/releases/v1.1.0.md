# Relationship Operating Framework v1.1.0

- **Planned release date:** 2026-08-22
- **Type:** Minor, documentation-only
- **Previous release:** [v1.0.0](https://github.com/BradGroux/relationship-operating-framework/releases/tag/v1.0.0)
- **Authorizing issues:** [#7](https://github.com/BradGroux/relationship-operating-framework/issues/7) and [#8](https://github.com/BradGroux/relationship-operating-framework/issues/8)

## Summary

Version 1.1.0 adopts Open Framework Commons v1.1.0 and adds the minimum
repository-stewardship surfaces needed to keep future changes inspectable. The
Relationship method, people-first commitments, human ownership of relationship
judgment and external action, and separation from Influence are unchanged.

## Commons adoption

Relationship independently adopts Open Framework Commons `v1.1.0`. Its
annotated tag object `79e5f06dab46f262cad1d1daf7840e683ffc3880`
peels to exact release commit
`f25a2b89b4aed95984fd235e2e229efe52c125d8`.

The Commons release recognizes Focus Operating Framework as a fifth independent
product and adds repository-stewardship surfaces. It does not change shared
principles or boundaries, automatically amend Relationship, import Focus
guidance, or transfer authority between ecosystem products. [Decision
0001](../../decisions/0001-adopt-open-framework-commons-v1.1.0.md) records the
local adoption with no deviations.

## Issue 7 audit disposition

| Finding | Disposition | Resolution |
|---|---|---|
| Missing `.github/` contribution surfaces | Accepted with narrower scope | Added owner routing, one product-local issue form, a pull-request template, and validation workflow. `CODEOWNERS` routes review but does not by itself guarantee branch-protection enforcement. |
| Alleged dead `scripts/validate-repository.sh` reference | Declined as factually incorrect | The v1.0.0 contributor guide explicitly said the release had no scripts and asked contributors to report manual or tool-assisted checks; it contained no script reference. Added validation prospectively for this release because the owner requested recompilation and testing and Commons v1.1.0 established a suitably bounded pattern. |
| Missing `decisions/` | Accepted prospectively | Added an index, template, and the current Commons v1.1.0 adoption decision. Declined retrospective v1.0.0 records because existing issues, governance, changelog, and review records already preserve that history without reconstructed approval. |
| Missing `framework/README.md` | Accepted | Added a canonical reading order and relationship diagram. |
| Missing `VERSION` | Accepted | Added `VERSION` as the machine-readable release version and synchronized it with citation and release metadata. |
| Missing `.gitignore` | Accepted | Added restrained rules for common local, private, and generated artifacts. |
| Empty GitHub topics | Accepted | Use restrained topics describing relationship stewardship, continuity, consent, human judgment, and documentation. |

## Compatibility

This is a backward-compatible minor release. It changes Commons adoption and
repository stewardship, not the Relationship practice. Historical v1.0.0
records and the v1.0.0 tag remain unchanged.

## Release gates

Before publication:

- validate version, citation, changelog, current Commons references, local
  Markdown links and anchors, Mermaid fences, and public hygiene;
- compile and visually inspect every tracked Mermaid diagram;
- validate citation metadata against the CFF 1.2 schema;
- scan the complete release diff for secrets with redacted output;
- complete practical, adversarial-misuse, canonical-coherence, and
  public-hygiene reviews against an exact candidate commit;
- compare the merged tree with the reviewed pull-request tree; and
- verify the annotated tag, GitHub release, topics, issue dispositions, and
  public identity through authenticated readback.

These gates establish documentation and publication integrity. They do not
claim real-world relationship effectiveness, consent, legal compliance,
professional fitness, or certification.
