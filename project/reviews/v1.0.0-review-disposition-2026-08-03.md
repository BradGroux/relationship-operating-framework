## Release decision

The corrected candidate is approved as the framework-content baseline for
version 1.0.0. It is useful without private context, remains documentation rather
than a system, adopts the exact Commons release while preserving independence,
keeps Relationship distinct from Influence, and labels unresolved proposals
honestly.

These public reports and this disposition are record-only additions made after
the corrected candidate was reviewed. They do not change canonical framework
meaning. Because their addition changes the repository tree, the release
maintainer must:

1. rerun link, metadata, secret, and public-hygiene checks on the complete pull
   request tree;
2. merge through the approved pull request;
3. compare the remote merged tree with the corrected candidate and the reviewed
   record-only additions; and
4. if the merged content differs from what was verified, rerun every affected
   validation and review against the merged commit before tagging.

No tag or release is authorized until those checks pass.
