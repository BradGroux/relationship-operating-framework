## Remaining release gates

These reports and this disposition are record-only additions after the reviewed
candidate. Before tagging, the release maintainer must:

1. change prepared metadata to accepted release state and record completed
   verification;
2. rerun repository, citation, diagram, secret, link, coherence, adversarial,
   practical, and public-hygiene checks on the complete pull-request tree;
3. merge through the approved pull request;
4. compare the remote merged tree with the final reviewed pull-request tree;
5. publish the annotated tag and release; and
6. verify issue responses, repository topics, identity, tag, and release through
   public readback.

No tag or release is authorized until those checks pass.
